# API Authentication

## وضعیت فعلی (صادقانه)

در ریلیز فعلی، **احراز هویت API وجود ندارد**. مدل اعتماد:

- سرور فقط روی `127.0.0.1` (loopback) گوش می‌کند — مرز اعتماد، خودِ دستگاه/
  شبکه‌ی داخلی است.
- سیستم کاربر/توکن وجود ندارد.
- این طراحی برای **تک‌کاربر** است؛ «سرویس داخلی» جایگزین کنترل دسترسی نیست.

## برای مصرف‌کنندگان بیرونی (planned)

طرح (Phase C + F):

1. **API Token** — tokenهای با-scope برای هر مصرف‌کننده (create/status/
   download و ...)؛ صدور/لغو توسط مدیر.
2. **Reverse proxy با TLS** روی زیردامنه‌ی سازمانی.
3. **Rate limiting** و **access control** بر پایه‌ی token.
4. **Correlation IDs** و **idempotency** برای عملیات ایمن.

تا آن زمان، هیچ راه‌کار رسمی برای دسترسی بیرونی وجود ندارد و نباید از
نقش تونل‌های شبکه‌ی داخلی برای «اطمینان» استفاده کرد.
