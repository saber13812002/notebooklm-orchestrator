# معرفی سرویس

**NotebookLM Orchestrator (NLO)** یک سرویس است که درخواست‌های «صوت +
دستور (prompt)» را به Google NotebookLM می‌فرستد، پردازش را به‌صورت نوبتی
(asynchronous) مدیریت می‌کند، و پاسخ و خروجی‌ها را در دسترس قرار می‌دهد.

## چه کار می‌کند؟

- یک فایل صوتی + یک دستور می‌دهید؛ سرویس آن‌ها را به NotebookLM واقعی
  می‌رساند و پاسخ **grounded** (بر پایه‌ی منبع) بازمی‌گرداند.
- پردازش **نوبتی** است: بلافاصله یک شناسه‌ی `job` دریافت می‌کنید و وضعیت را
  بعداً پیگیری می‌کنید.
- چند حساب گوگل و چند نود VLESS را مدیریت می‌کند؛ هر job یک حساب و یک مسیر
  خروج سالم را (خودکار یا دستی) انتخاب می‌کند.
- هر درخواست آرشیو می‌شود: ورودی، snapshot پیکربندی، timeline، تلاش‌ها و
  خروجی‌ها.
- خروجی‌ها را می‌توان از API دانلود کرد (پاسخ Markdown + فایل‌هایی که
  provider واقعاً تولید کرده است).

## وضعیت واقعی قابلیت‌ها

| قابلیت                                 | وضعیت                              |
| -------------------------------------- | ---------------------------------- |
| پردازش واقعی صوت→پاسخ با NotebookLM    | live-verify شده                    |
| مدیریت حساب‌های گوگل و نودهای VLESS    | live-verify شده                    |
| API نوبتی job (ایجاد/وضعیت/دانلود/لغو) | تست‌شده                            |
| Webhook                                | **planned** (هنوز پیاده‌سازی نشده) |
| احراز هویت API برای دسترسی بیرونی      | **planned**                        |
| Google Drive / DOCX / خروجی‌های Studio | **planned**                        |

## مدل دسترسی (مهم)

در وضعیت فعلی، سرویس **تک‌کاربر و loopback-only** است: فقط روی
`127.0.0.1` گوش می‌کند و سیستم کاربر/توکن ندارد. مصرف‌کنندگان بیرونی (سامانه‌های
ثالث) پس از پیاده‌سازی Token Auth و reverse proxy (فازهای بعدی) پشتیبانی می‌شوند.
